# Nexus - 内网穿透服务

Nexus 是一个内网穿透服务，旨在提供安全、高效的内部网络资源访问能力。本项目分为客户端和服务端两个主要部分，分别位于 `@client/` 和 `@internal/` 目录下。

## 1. 项目架构

Nexus 采用经典的客户端-服务端（C/S）架构。客户端部署在需要访问内网资源的设备上，通过与部署在公网的服务端建立连接，实现内网资源的代理访问。服务端负责管理客户端连接、认证、心跳维护以及数据转发。

### 核心组件：

- **客户端 (`@client/`)**: 负责与服务端建立连接，处理本地应用的网络请求，并通过隧道将请求转发至服务端，接收并处理服务端的响应。
- **服务端 (`@internal/`)**: 监听客户端连接，进行身份验证，维护客户端会话，并根据客户端请求将数据转发至目标内网服务，再将响应返回给客户端。

## 2. 消息通信协议

Nexus 的消息通信协议基于 TCP 协议之上，设计了一套自定义的应用层协议，以实现客户端与服务端之间的认证、心跳保持和数据隧道传输。具体协议细节（例如消息头、消息体结构、加密方式等）将在后续详细说明或通过代码注释体现。

### 主要通信流程：

1.  **认证阶段**: 客户端连接服务端后，首先进行身份认证，确保连接的合法性。
2.  **心跳保持**: 认证成功后，客户端与服务端会定期发送心跳包，以维持连接的活跃状态并检测对方的在线状态。
3.  **数据隧道**: 认证和心跳机制建立后，客户端与服务端之间会建立一个或多个数据隧道，用于转发实际的应用层数据。

## 3. 项目结构

### `@client/` (客户端)

-   `client.go`: 客户端主逻辑，负责连接管理、启动等。
-   `main.go`: 客户端程序的入口点。
-   `handler/`: 存放客户端侧的请求处理逻辑。
    -   `sys.go`: 系统相关处理，例如配置加载、日志等。
    -   `tunnel.go`: 隧道数据转发和处理逻辑。

### `@internal/` (服务端)

-   `config/`: 存放服务端的配置相关代码。
    -   `config.go`: 服务端配置的定义和加载。
-   `dao/`: Data Access Object 层，负责数据库操作。
    -   `app.go`: 应用相关的数据库操作。
    -   `base.go`: 基础数据库操作。
    -   `client.go`: 客户端信息相关的数据库操作。
-   `database/`: 数据库连接和初始化。
    -   `database.go`: 数据库连接管理。
-   `handler/`: 服务端请求处理逻辑。
    -   `auth.go`: 认证请求处理。
    -   `handler.go`: 通用请求处理器。
    -   `heartbeat.go`: 心跳请求处理。
-   `model/`: 数据库模型定义。
    -   `app.go`: 应用模型。
    -   `base.go`: 基础模型。
    -   `client.go`: 客户端模型。
-   `server/`: 服务端核心逻辑。
    -   `server.go`: 服务端启动和管理。
    -   `tcp.go`: TCP 连接管理和监听。
-   `service/`: 业务逻辑层。
    -   `app.go`: 应用相关业务逻辑。
    -   `client.go`: 客户端相关业务逻辑。
    -   `service.go`: 通用业务逻辑。
    -   `tunnel.go`: 隧道业务逻辑。
-   `session/`: 会话管理。
    -   `manager.go`: 会话管理器。
    -   `session.go`: 会话定义。
